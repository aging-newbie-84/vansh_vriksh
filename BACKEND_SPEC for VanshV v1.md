# Vansh Vriksha — Backend Specification
## For Anti Gravity / Claude Code

---

## Architecture Overview

The backend is orchestrated through **n8n** — a no-code/low-code workflow automation tool. There is no custom Node.js or Python server required for Phase 1. All intelligence lives in n8n workflows that call the OpenAI or Claude API.

```
Frontend (React) 
    │
    │  POST /webhook/family-parse
    ▼
n8n Workflow Engine
    ├── Input Preprocessing Node (Code)
    ├── AI Model Node (OpenAI GPT-4o or Claude)
    ├── Output Validation Node (Code)
    └── Response Node
    │
    │  JSON response
    ▼
Frontend (renders preview)
```

## n8n Workflow: `family-parser-workflow`

### Node 1: Webhook Trigger

```
Type: Webhook
HTTP Method: POST
Path: /family-parse
Response Mode: Last Node
Authentication: None (Phase 1) / Header Auth (Phase 2)
```

**Expected Request Body:**
```json
{
  "transcript": "string — raw audio transcript or typed text",
  "session_id": "string — UUID generated by frontend",
  "previous_parse": "object | null — last JSON parse from this session",
  "correction": "string | null — user's correction instruction if editing"
}
```

---

### Node 2: Input Preprocessor (Code Node)

```javascript
// Clean spoken language artifacts
const items = $input.all();
const item = items[0].json;

const raw = item.transcript || '';
const correction = item.correction || null;
const previousParse = item.previous_parse || null;

// Clean filler words common in Indian spoken English
const cleaned = raw
  .replace(/\b(um+|uh+|hmm+|you know|like I said|basically|actually|so yeah|na|nahi|matlab)\b/gi, ' ')
  .replace(/\s{2,}/g, ' ')
  .trim();

// Build the user message based on context
let userMessage;

if (correction && previousParse) {
  userMessage = `
Here is the current family tree parse:
${JSON.stringify(previousParse, null, 2)}

The user wants to make this correction: "${correction}"

Please apply this correction and return the complete updated JSON.
  `.trim();
} else if (previousParse) {
  userMessage = `
Here is what we've mapped so far:
${JSON.stringify(previousParse, null, 2)}

The user has added more family information:
"${cleaned}"

Please incorporate this new information and return the complete updated JSON with all people from before plus any new ones.
  `.trim();
} else {
  userMessage = `
Please parse this family history narrative and build a family tree:

"${cleaned}"

Return the complete JSON structure.
  `.trim();
}

return [{ json: { userMessage, sessionId: item.session_id } }];
```

### Node 4: Output Validator & Parser (Code Node)

```javascript
const items = $input.all();
const rawResponse = items[0].json;

// Handle both OpenAI and Claude response formats
let rawText;
if (rawResponse.choices) {
  // OpenAI format
  rawText = rawResponse.choices[0].message.content;
} else if (rawResponse.content) {
  // Claude format
  rawText = rawResponse.content[0].text;
} else {
  rawText = JSON.stringify(rawResponse);
}

// Strip markdown fences if present
const cleanJson = rawText
  .replace(/^```json\s*/i, '')
  .replace(/\s*```$/, '')
  .trim();

let parsed;
try {
  parsed = JSON.parse(cleanJson);
} catch (e) {
  // If JSON parse fails, return error structure
  return [{
    json: {
      error: true,
      message: "Could not understand the family history. Please try again or simplify the narrative.",
      raw: rawText,
      parse_version: 0,
      people: [],
      ambiguities: [],
      nudge_questions: ["Could you describe your family in simpler terms? Start with one person and their children."]
    }
  }];
}

// Validate required fields exist
if (!parsed.people || !Array.isArray(parsed.people)) {
  parsed.people = [];
}
if (!parsed.ambiguities) parsed.ambiguities = [];
if (!parsed.nudge_questions) parsed.nudge_questions = [];
if (!parsed.relationships) parsed.relationships = [];

// Assign sequential IDs if missing
parsed.people = parsed.people.map((person, index) => ({
  ...person,
  id: person.id || `p${index + 1}`
}));

return [{ json: parsed }];
```

## Data Models

### Person Object
```typescript
interface Person {
  id: string;                    // "p1", "p2", etc.
  name_display: string;          // Full formal name
  name_variants: string[];       // All nicknames/variants
  gender: 'M' | 'F' | 'U';     // U = unknown
  birth_decade: string | null;   // "1940s", "early 1960s"
  death_decade: string | null;
  is_deceased: boolean;
  location_origin: string | null;
  location_current: string | null;
  profession: string | null;
  personality_trait: string | null;
  one_liner: string | null;      // "Cuttack · Clerk · Remembered every date"
  marriages: Marriage[];
  notes: string | null;          // Free-form AI notes
}

interface Marriage {
  spouse_id: string;
  status: 'married' | 'separated' | 'divorced' | 'widowed' | 'partner';
  is_current: boolean;
  children_ids: string[];
}

interface Relationship {
  person_a_id: string;
  person_b_id: string;
  type: 'parent-child' | 'spouse' | 'sibling' | 'other';
  direction: string;
}

interface ParseResult {
  parse_version: number;
  root_person_id: string;
  confidence: 'high' | 'medium' | 'low';
  people: Person[];
  relationships: Relationship[];
  ambiguities: Ambiguity[];
  nudge_questions: string[];
  summary: string;
}
```

## Session Management

Phase 1: Session state managed entirely on the frontend (React state + localStorage). No database required.

Phase 2 (future): Add a simple Supabase table:

```sql
CREATE TABLE sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id TEXT UNIQUE NOT NULL,
  parse_data JSONB,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

## Rate Limiting & Cost Management

### Estimated Costs per Session
- Average transcript: ~500 tokens input
- Average parse response: ~800 tokens output
- GPT-4o cost: ~$0.01 per full session
- Claude Sonnet cost: ~$0.005 per full session

### n8n Rate Limiting
Add a "Wait" node set to 1 second between webhook receipt and AI call to prevent abuse. For Phase 2, add IP-based rate limiting at the n8n level.

## Error Handling Matrix

| Error | User-Facing Message | Action |
|-------|-------------------|--------|
| API timeout | "Taking a bit long — please try again" | Retry button |
| JSON parse fail | "Couldn't understand that — try simpler language" | Re-show input |
| Empty transcript | "We didn't catch anything — please speak louder or type" | Re-show input |
| Network error | "Connection issue — your draft is saved" | Offline indicator |
| Rate limit | "Too many requests — please wait a moment" | Cooldown timer |

## Deployment Notes

### n8n Deployment Options
1. **n8n Cloud** (recommended for Phase 1) — no server management
2. **Railway.app** — simple self-hosted n8n
3. **Docker on VPS** — full control

### CORS Configuration
Frontend must be whitelisted in n8n webhook CORS settings or add a reverse proxy (nginx/Cloudflare) in front of n8n.

### Webhook URL Structure
```
Production:  https://your-n8n.cloud/webhook/family-parse
Development: http://localhost:5678/webhook/family-parse
```

Set in frontend `.env`:
```
VITE_N8N_WEBHOOK_URL=https://your-n8n.cloud/webhook/family-parse
```
